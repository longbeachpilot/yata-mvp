# YA TA 전체 흐름 검증 — 2026-09-28

## 판정 원칙

오류가 절대 없다는 보장은 하지 않는다. 화면, API 응답, DB 권한·규칙을 나누어 확인하고 실제로 확인한 범위와 남은 범위를 구분한다. 브라우저 계약 검사는 API를 가상 응답으로 대체하므로 운영 서버 전체를 통과한 실거래 증거가 아니다.

## 발견하여 수정한 항목

| 문제 | 수정 및 재발 검사 |
|---|---|
| 교관 신규 등록/지역 수정이 검색지역에 반영되지 않음 | 프로필 저장과 같은 DB 트랜잭션에서 검색지역 동기화. 신규 등록 직후 지역 0건을 재현한 뒤 실제 DB의 등록·수정 검사를 추가 |
| 검색어를 지워도 이전 지역 필터가 남음 | 빈 검색은 전체 지역으로 초기화. 검색 실패 뒤 이전 교관/위치가 새 결과처럼 남지 않게 처리 |
| 별도 교관 목록에서 강남/강남구 표기가 달라 누락 | 지역명 비교 함수를 재사용하며 이름·차량 검색은 유지 |
| 홈페이지 조회 실패를 교관 없음으로 표시 | 불러오는 중/조회 실패/실제 빈 목록 구분 |
| 관리자 교관 목록의 권한·비로그인 처리 혼동 | 비로그인은 로그인으로 이동, 비관리자는 명확한 거절, 조회 실패 시 이전 목록 제거 및 재시도 |
| 공개 중 교관의 보험 확인을 다시 누르면 비공개 처리 | 보험 재확인 시 현재 공개 상태 유지, 명시적 보류 버튼으로 비공개 처리 |
| 프로필 저장의 실패·빈 응답을 충분히 처리하지 않음 | 저장된 행을 확인하고 성공 처리. 실패 시 입력 보존, 버튼 복구, 재시도 |
| 교관 등록/로그아웃의 예외 처리 누락 | 오류 안내·중복 클릭 방지·버튼 복구. 등록 성공 후 즉시 교관센터 이동 |
| 인증 완료 후 교관도 일반 검색으로 이동 | 실제 계정 프로필과 관리자 권한을 조회하여 교관센터/등록/관리자로 이동 |
| 복구 메일 제한 등에서 내부 영문 오류 노출 | 복구 만료·발송 제한·비밀번호 변경 실패를 사용자 안내로 표시 |
| 과거·잘못된 시간·예약 중인 시간 재개방 가능 | 화면의 미래 시간 검사와 DB 시간 형식·충돌 검사 추가 |
| RPC 외 직접 쓰기로 불완전한 수업 기록 저장 가능 | 수업 기록·숙련도·후기는 검증 RPC만 쓰도록 직접 DML 권한 회수 |
| 존재하지 않는 날짜를 JavaScript가 다음 달로 보정 | 시간 유효성 검사에 실제 달력 날짜 확인 추가 |
| 교관 모집 화면이 미구현 결제·정산을 약속 | 구현된 예약·수업 관리 기능으로 문구 수정 |

지역은 쉼표 등으로 구분해 `서울 강남구, 경기 성남시 분당구`처럼 각각 입력한다. 교관의 공개 상태, 실제 활동범위, 가격, 고객 예약을 임의로 변경하지 않는다. 기존 검색지역은 유지하며 프로필의 활동지역을 실제로 바꿀 때 새 지역에 맞춰 갱신한다.

DB 4개 검사 파일은 변경 SQL과 함께 각각 하나의 트랜잭션으로 실행하여 모두 통과했고 ROLLBACK했다. 인증 메일이나 운영 예약을 생성하지 않았다. 시작 시 운영 예약 6건, 교관 5명, 검색지역 8건, example.invalid 테스트 계정 0명이었다. 운영 사용자가 동시 이용 중이므로 이후 전체 행수 증가는 테스트의 변경으로 간주하지 않는다.

DB 변경은 `20260928071903_sync_profile_regions_and_protect_lesson_writes`로 적용했다. 적용 후 신규 교관 검색·일정 충돌·취소 검사와 기존 예약 운영·기록·후기 검사를 다시 통과시켰다. 모든 검사 데이터는 ROLLBACK했다.

브라우저 검사는 GitHub Actions의 `Quality`에서 Chromium으로 실행한다. 계정·메일·지도·DB 응답은 격리된 fixture이며 예기치 않은 외부 요청과 브라우저 예외가 있으면 실패한다. 각 커밋의 CI 성공 여부와 로그를 최종 실행 증거로 사용한다. 모바일 390px와 기존 관리자 데스크톱 1440px를 포함한다.

## 아직 검증 완료라고 말할 수 없는 부분

- 실제 iPhone/Safari에서 실제 인증메일을 열고 서로 다른 학습자·교관 계정으로 진행하는 전 과정. 실제 메일 발송 한도·지연·스팸함 수신은 가상 테스트가 입증하지 않는다.
- 실제 학원, 차량·보험, 가격·수업 가능 지역/일정, 수업 이행, 직접 결제·환불. 앱의 완료 상태는 실제 교육 제공을 증명하지 않는다.
- 동시 다수 사용자의 부하·장시간 운용, 모든 기기·네트워크 조건, 백업 복원 훈련. 현재 잠금과 중복 제약 검사는 다중 세션 부하 검사를 대체하지 않는다.
- Vercel 과거 runtime 오류 로그: 연결 도구가 `403 Forbidden`을 반환해 조회 미완료. 로그가 깨끗하다고 판정하지 않는다.
- Supabase 유출 비밀번호 보호가 비활성화되어 있다. [공식 안내](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). private 테이블의 RLS 정책 없음은 직접 접근 차단 설계이며, SECURITY DEFINER RPC는 권한 검사와 테스트로 검토했다. 보안감사 인증을 의미하지 않는다.
- 정식 약관·개인정보 처리방침 및 동의 이력, 제휴 조건 확정은 `OPERATING_READINESS_2026-09-27.md`의 별도 출시 과제로 남는다.
