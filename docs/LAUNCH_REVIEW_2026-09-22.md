## 판정

이번 수정으로 핵심 권한·예약 검증·프로필 저장 결함을 개선했습니다. 아직 유료 정식 출시 준비 완료로 판정할 수는 없습니다. 실제 미래 일정 공급이 없고, 현재 약관/개인정보처리방침은 테스트용이며 결제·정산은 구현되지 않았습니다.

점검 당시 집계: 공개 교관 5명, 시스템 예약 필수조건 충족 교관 1명, 미래 공개 가능시간 0개. 개인정보나 실사용자 계정을 보고서에 복사하지 않았습니다. 이 숫자는 점검 시점의 상태이며 학원 제휴·법적 자격 확인을 의미하지 않습니다.

## 검증 결과

- 기존 코드와 수정 코드 모두 타입 검사·프로덕션 빌드 통과. 수정 후 CSS 경고 제거.
- `npm test`: 로그인 복귀 경로, 한국 시간 경계, 지역 일치 3개 테스트 그룹 통과.
- `npm audit --omit=dev`: 검사 당시 알려진 취약점 0건.
- 운영 DB 구조에서 수정 DDL+회귀 테스트를 트랜잭션으로 실행한 뒤 전체 롤백. 이후 `launch_hardening` 마이그레이션 적용 성공. 적용 후 동일 테스트 재실행 통과.
- DB 테스트는 합성 사용자·예약만 사용하고 모두 롤백. 허용 프로필 수정, 금지 role 수정, 관리자/비공개 자격 권한, 과거시간, 수업 길이, 자정 경계, 같은 슬롯/겹치는 슬롯/학습자 중복 예약, 서버 가격, 보험 자가인증 차단 확인.
- 실제 Chromium 모바일 390px에서 브라우저 계약 테스트 통과: 예약 선택 → 로그인 → 선택 복원 → 예약 요청, 모바일 메뉴 갱신, 비공개 자격 조회/저장 payload, 보험 읽기 전용, 검색 API 실패 표시, 가로 넘침/미처리 브라우저 오류 없음.
- 브라우저 테스트의 인증·DB API 응답은 모의 데이터입니다. 운영 이메일 발송, 실제 로그인 계정, 결제, 실제 카카오 지도 외부 통신을 통과했다는 의미는 아닙니다. DB 계층은 별도로 실제 Postgres 트랜잭션 테스트로 검증했습니다.

## 출시 전 남은 조건

1. **실제 공급:** 제휴 교관/학원별 확인을 마친 뒤 미래 가능시간과 서비스 지역 등록. 가짜 가능시간은 생성하지 않았습니다.
2. **운영 문서:** 현재 `/terms`, `/privacy`의 테스트용 문구를 실제 운영주체·연락처·취소/환불·보유기간·처리위탁 등에 맞춰 확정. 미확정 사업 사실을 만들어 넣지 않았습니다.
3. **유료 서비스:** 현 서비스는 예약 요청까지이며 결제·정산이 없음. PG/환불/학원 정산 흐름을 검증하기 전 유료 결제 가능 서비스로 안내하면 안 됩니다.
4. **실제 계정 최종 확인:** 출시 도메인에서 이메일 인증/비밀번호 복구, 실제 카카오맵 허용 도메인, 학습자 예약 → 교관 확정/완료 → 로그북/후기까지 승인된 테스트 계정으로 확인. 실제 메일을 보내거나 사용자 예약을 만들지 않았습니다.
5. **인증 설정:** 유출 비밀번호 보호가 비활성화되어 있음. 운영 설정 검토 필요. [Supabase 공식 안내](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
6. **DB 이력:** 과거 변경 일부가 저장소에 없음. `supabase/README.md`에 따라 기준 스키마/마이그레이션 이력을 정리한 뒤 새 staging 환경 구성. 이전 설치 파일 재실행 금지.

추가로, 겹치는 공개 시작시간이 목록에 남아 있을 수 있으나 최종 예약 RPC는 충돌을 거절합니다. 실제 수업 일정에 맞춰 공개 시작시간을 관리해야 합니다. 이번 테스트는 동시 요청 부하/침투 테스트나 법률 적합성 인증을 대신하지 않습니다.
